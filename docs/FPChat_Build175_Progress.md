## Правила и исходные ревизии

Каждая сборка сохраняет 100% существующего функционала. Миграция меняет владельца существующей логики; один перенос — отдельный commit, regression и точечный rollback. Следующий владелец не переносится до подтверждения предыдущего. Рабочие сценарии 168 сохраняются; подтверждённые дефекты не являются эталоном.

- Поведенческая база: Build 168, `9c53a7a0329f267a51c7e976f1c4c825d9b7ae42`.
- Исходная накопительная 174: `1fc1150d30502f9970ef9b81e01619fd62964c86`. Совпадение локальной и удалённой development-ветки проверено перед началом.
- Удалённая `main` при проверке: `4a7da1877f029b4fb5b1300ff84ae7ea541cb69e`, последний коммит — изменение документации о сохранении поведения. `main` и работающий сервер этим этапом не изменяются.
- Исходная рабочая копия чистая. Для 175 создан отдельный git worktree; 168 и 174 сохранены для сравнения.

Среда: Linux Chromium, runner Node 24.19.0, сервер Node 22.20.0; production bootstrap с временной SQLite и тестовыми данными. Использованы уже установленные зависимости, `npm install` не выполнялся. 52 браузерных сценария не являются доказательством проверки всех функций или мобильной приёмки.

Новый сценарий через настоящую отправку текста воспроизвёл дефект **на 168 и 174**: поле ввода очищено, сообщение сохранено один раз, а микрофон остаётся скрытым и disabled. Ручной input восстанавливает его. Причина в проверенном пути: программная очистка textarea не уведомляет существующий `voice.js/syncComposer`.

Контрольные сценарии без изменения кода: пустой composer, ввод/ручное удаление текста, повторные открытия комнат и отдельные draft проходят. На 168 дополнительно воспроизведено неверное отображение кнопок после восстановления непустого draft. Изолированная задержка draft и соседние voice/edit-сценарии проверяются в 175.1.
