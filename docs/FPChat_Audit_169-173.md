## Решение

## Воспроизводимые проверки

Без внешних пакетов:

```sh
npm run check:169-173
```

Результат: все пять проверок **PASS**. 170–172 теперь допускают интегрирующую Build 173; прежние проверки ошибочно требовали свой точный номер и устаревшую loader chain. Это static/VM проверки, а не доказательство полного UX-покрытия.

Браузерная интеграция:

```sh
npm run test:173:browser
```

Нужны уже установленные Playwright, Chromium и серверные зависимости. Если они находятся отдельно, поддерживаются `NODE_PATH`, `BROWSER_EXECUTABLE_PATH` и `FPCHAT_TEST_NODE` (Node, совместимый с установленным native `better-sqlite3`). Скрипт запускает production bootstrap локально на свободном порту, использует временную SQLite и независимые браузерные профили, затем закрывает процессы и удаляет временную БД. Рабочая БД и push-подписки не используются.

Среда проведённого прогона: Linux, headless Chromium, Node 22 для сервера; Node 24 для тестового runner. Результат: **17 PASS, 0 FAIL**:

1. Загрузка владельцев 169–173 и честное partial coverage диагностики.
2. Поздний render A после открытия B.
3. Смена generation A → B → A.
4. Уход во время anchor hydration.
5. Поздний draft и новый ввод.
6. Шифрование draft A при открытой B.
7. Echo перед ACK, reply dependencies и монотонный статус.
8. Pins/attachment modal и запрет нижнего жеста.
9. Отмена upload до отправки XHR.
10. Ограничение загрузок до завершения response body.
11. Дедупликация cache writes, clear guard и delete.
12. Отправка текста при A → B, двойной submit, сохранение ввода B.
13. Завершение media A при открытом preview B.
14. Оба сообщения об отказе invite из-за блокировки.
15. Поздний успешный invite после ухода в настройки.
16. Два клиента: invite с единственным lifecycle ready, text, ACK, reply, edit, delete, reconnect и один WS.
17. Отсутствие необработанных исключений браузера.

Media-send сценарий 13 перехватывает WS payload и проверяет room/key/preview; он не заменяет передачу реального файла. Сценарий 10 использует управляемые `ReadableStream`; сценарии 2–5 и 15 задерживают конкретные ответы. Полный progress/cancel/error UX реальной загрузки, autoplay, запись voice, push, весь block/unblock/presence/typing UX, background/foreground и длительная история этим прогоном не закрыты.

## Откат

Изменения этой доработки фиксируются одним отдельным commit в `build/173-development`. Откат — `git revert` этого commit; затем штатный запуск `npm start` и прежняя `npm run check:173`. Новый общий runner при откате также удаляется. Для воспроизведения состояния до аудита использовать отдельный checkout ревизии `d98d319199a2cb961201726bb556ada69e9a0658` (её прежние check170–172 имеют описанные ограничения).

Формат SQLite, cache name `fpchat-media-v167`, protocol и persistent queue не изменены; миграция пользовательских данных для этого отката не требуется. `main` остаётся на Build 168. Слияние в `main` требует отдельного решения после приёмки.
