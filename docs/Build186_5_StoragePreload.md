# Build 186.5 — предварительная загрузка хранилища

Ветка: `build/186-development`. Основа: 186.4 (`54429db`).

## Почему

В физических отчётах 186.4 подготовка приложения заняла 2256 и 4358 мс. После готовности UI оставалось 497 и 618 мс ожидания ресурсов. Последними загружались storage167-clear-guard.js, storage167-cache-fix.js и storage168.js: каждый следующий запрос начинался только после выполнения предыдущего файла.

Открытие чата при этом было быстрым: показ 100 сообщений через 605/663 мс, шесть миниатюр из кэша готовы через 365/406 мс. Изменение 186.5 ограничено подготовкой приложения.

## Изменение

После успешной готовности существующих владельцев `FPStartup174.ready` загрузчик добавляет четыре script-preload с низким приоритетом: storage167.js, storage167-clear-guard.js, storage167-cache-fix.js, storage168.js. Все используют текущий суффикс версии.

Предварительная загрузка только получает файлы. Их выполнение по-прежнему запускает существующая последовательность onload в build165-ui.js. Сохранены проверки готовности, задержки/таймауты, порядок подключения сетевых и кэш-слоёв, ошибки цепочки, обновление и прямой вход по ссылкам. При провале обязательных владельцев новые подсказки загрузки не добавляются. Нового загрузчика/менеджера и дополнительных зависимостей нет.

Низкий приоритет — подсказка браузеру; её фактическое применение зависит от браузера. Если preload не поддержан, остаётся прежняя последовательная загрузка. Изменение не устраняет задержку проверки version.json или всю цепочку интерфейса.

## Проверки

`npm run test:186:storage-preload` проверяет:

- старт предварительной загрузки после готовности основных владельцев;
- загрузку последующих файлов при удержанном storage167 без преждевременного выполнения;
- сохранение заставки до готовности ресурсов;
- один запрос и одно выполнение каждого файла, правильный порядок и единого владельца сети/кэша;
- повторную навигацию;
- ошибку clear guard: предварительно загруженные последователи не обходят остановку существующей цепочки.

`npm run test:186` включает эту проверку и всю предыдущую регрессию запуска, обслуживания кэша, диагностики, медиа, reply, увеличения фото, жестов и очистки кэша.

Полный `npm run test:186` прошёл в Linux Chromium: 5 новых сценариев предварительной загрузки и все включённые регрессии предыдущих сборок. Физическая проверка на устройстве остаётся отдельным этапом.

## Локальное сравнение с 186.4

Команда: `FPCHAT_BOOT_BASE_REF=54429db82b89091f9d01eee0bf8615a0644b40f1 npm run bench:186:startup` (с BROWSER_EXECUTABLE_PATH на установленный Chromium).

Три пары свежих профилей, замедление CPU 4×, одинаковая добавленная задержка каждого запроса 80 мс. Порядок baseline/current чередовался. Пропускная способность не ограничивалась; маршрутизация выключает HTTP-кэш с обеих сторон. Предварительно полученные файлы переиспользуются браузером внутри текущей навигации. Подменяются index.html и boot-ready152.js из 186.4; остальные файлы одинаковы.

Разница медиан — 284.3 мс, около 18%. Готовность основных владельцев в сопоставимом диапазоне (186.4: 485.7–521.9 мс; 186.5: 473.7–505.1 мс). Все readiness-проверки завершились успешно, ошибок страницы нет. Это локальное сравнение, не измерение физического телефона и не гарантия такого же процента на другом соединении.

## Физическая приёмка

1. Обновиться до **186.5**, дождаться обновления и проверить номер сборки.
2. Полностью закрыть и открыть приложение, открыть большой проблемный чат и фото.
3. Скачать отчёт через «Настройки → О приложении → Скачать отчёт загрузки».
4. Повторить полный запуск и открыть тот же чат/фото; скачать второй отчёт.
5. Сохранить медиакэш. Проверить reply, голосовое, увеличение фото, отправку и возврат в список.

По отчётам сравнить общую подготовку, момент готовности владельцев и завершения storage-файлов. Время в boot.assets — наблюдение загрузчика, а не отдельный замер сетевой передачи или выполнения JS.
