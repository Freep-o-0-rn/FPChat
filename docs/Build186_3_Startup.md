# Build 186.3 — подготовка приложения

Продолжение 186.2 в `build/186-development`. Цель — сократить ожидание стартового экрана, сохранив существующих владельцев и порядок исполнения.

## Изменения

- Шесть скриптов поздней цепочки владельцев заранее загружаются через preload, пока запускается app.js. Исполнение по-прежнему запускают существующие onload-зависимости.
- Стартовый экран больше не ждёт дополнительного system refresh и завершения запроса списка заявок. Их существующие владельцы продолжают первоначальную и последующую синхронизацию; данные могут появиться после открытия интерфейса.
- После готовности ядра и UI проверяются отслеживаемые JS/CSS, затем два кадра отрисовки и повторная проверка. Убраны фиксированные ожидания тишины 180 мс и дополнительная задержка 120 мс.
- В отчёте загрузки добавлены `assets-start`, `assets-end` и признак завершения проверки ресурсов. Старые названия этапов сохранены в допустимом наборе для сравнения отчётов.

## Сохранённые границы

Не изменены app.js, сервер, владельцы жестов/отправки/истории/кэша, проверка обновления, Service Worker и порядок входа в чат. Сохранены проверки ядра, всех 16 UI-флагов, таймауты 9/7/4 секунды и аварийное снятие заставки через 15 секунд. При таймауте возможен прежний ограниченный режим готовности; `completed: false` в отчёте нельзя считать полной готовностью.

## Проверки

`npm run test:186:startup` проверяет граф и координацию запуска, порядок исполнения владельцев, однократное раскрытие интерфейса, задержанные фоновые ответы, задержку CSS, ошибки обязательных/необязательных ресурсов, прямой вход с доступом и без него, приглашение и реальный путь обновления с перезагрузкой.

`npm run test:186` включает эти проверки и существующие проверки диагностики, медиа-кэша, увеличения фото, reply, жестов, уведомлений, микрофона и управления ресурсами.

Полный `npm run test:186` завершился успешно в Linux Chromium: новые 9 сценариев запуска, 9 сценариев медиа-кэша, 12 сценариев диагностики и все включённые регрессии предыдущих сборок. Физическая приёмка остаётся отдельным этапом.

Для браузерных проверок задайте `BROWSER_EXECUTABLE_PATH` на доступный Chromium.

## Локальное сравнение

`npm run bench:186:startup`: три пары свежих профилей Chromium; замедление CPU 4×, задержка каждого запроса 80 мс, одинаковая политика HTTP-кэша. Пропускная способность не ограничивалась. Сравниваются index.html и boot-ready152.js из 186.2 с текущими; остальные файлы одинаковы.

| Вариант | Замеры подготовки, мс | Медиана, мс |
| --- | --- | --- |
| 186.2 | 1923.9 / 1877.3 / 1858.8 | 1877.3 |

В этом локальном эксперименте выигрыш составил около 285 мс (15%). Это не результат измерений iPhone/Android и не гарантия такого же ускорения на устройстве.

## Физическая приёмка

1. Обновиться до 186.3, дождаться завершения обновления. Проверить номер в «О приложении».
2. Полностью закрыть приложение и открыть снова при стабильном интернете. Сохранить «Настройки → О приложении → Скачать отчёт загрузки».
3. Проверить список чатов и заявок, вход в проблемный чат, отправку текста, reply, запись голоса, фото и увеличение, возврат в список.
4. Снова полностью закрыть и открыть приложение, сохранить второй отчёт. Очистка замеров без нового запуска не создаёт нового измерения подготовки. Медиа-кэш для этого сравнения очищать не требуется.
5. Повторить на слабом Android и iPhone. Отдельно проверить вход по приглашению. Первый запуск при обновлении сравнивать отдельно от обычных запусков.

Отключение интернета из предыдущего пользовательского отчёта не рассматривается как ошибка приложения.
