# Build 184.6 — Reply Swipe UI: отчёт и физическая приёмка

Дата: 2026-09-23. Ветка: `build/184-development`.

**Статус: реализация и автоматическая приёмка завершены; готово к проверке на физических устройствах.**

## Основа

При начале работы ветка 184 указывала на `a81e0b91dfada282d190061e1b269b82b126ecc8`.
В ней были неподключённые заготовки индикатора поверх Build 180.14.
Сначала в неё включён Build 183.9 (`4ffcd642ba068da5d12356c0f43851dbfbded87e`),
чтобы сохранить предыдущие изменения уведомлений, микрофона и chat-back.
Слияние выполнено без конфликтов.

Текущий reply найден в `appendMessage()` в `public/app.js` версии 183.9:

| Что | Действующий код |
|---|---|
| Создание прежнего круга | `.swipe-reply-icon` рядом с `.bubble` |
| Движение сообщения | `bubble.style.transform`, смещение ограничено −110 px |
| Прогресс | `Math.min(1, Math.abs(currentDx) / SWIPE_REPLY_THRESHOLD)` |
| Порог | `SWIPE_REPLY_THRESHOLD = 52` |
| Допуск | `FPGesture135.currentLayer()` и lease `message-reply-swipe` |
| Выполнение | `setSelectedReply(state.roomId, getMessageReplyMeta(m.id))` при отпускании |

`swipe-fix.js` отвечает за навигацию, а не за этот индикатор.

## Реализация

Владельцем жестов остаётся `FPGesture135`, выбором reply управляет прежний обработчик.
`FPReplySwipeVisual184` только создаёт и обновляет DOM по переданным `progress` и `armed`.
Новых ReplyManager, AnimationManager или GestureManager нет.
Неиспользовавшаяся дублирующая заготовка `reply-indicator-view.js` удалена.

| Этап | Результат |
|---|---|
| 184.1 | Проверена реализация 183.9, согласована основа ветки |
| 184.2 | Подключён визуальный исполнитель; DOM появляется только при первом свайпе строки; точка 8 px растёт до круга 36 px |
| 184.3 | Появляющаяся SVG-стрелка и armed от существующего обработчика |
| 184.4 | Отдельный ripple: scale 1 → 1.7, opacity 0.45 → 0, 220 ms |
| 184.5 | Отмена, сброс при смене слоя/комнаты, проверки регрессий |
| 184.6 | Проверены скриншоты и браузерные сценарии; версия, cache-bust и updater согласованы; физическая приёмка ожидается |

Первые 12% прогресса показывают точку. Затем диаметр увеличивается от 8 до 36 px.
Размер меняется через `transform`, без перерасчёта ширины/высоты строки.
SVG плавно становится видимой и увеличивается. Порог ответа остаётся **52 px**.
Ripple запускается один раз за жест, включая удержание и возвращение ниже порога с повторным пересечением.
После отпускания ниже порога индикатор исчезает за 140 ms, reply и черновик не меняются.
При `prefers-reduced-motion: reduce` ripple и переходы отключены.

Сброс предусмотрен для touchcancel, второго касания, вертикального движения,
выхода из комнаты, blur, повышения слоя и удаления сообщения до touchend.
Захваченный RoomContext предотвращает поздний reply в другой комнате.
Таймер возврата старого жеста отменяется перед следующим жестом той же строки.

JS и CSS визуального исполнителя запрашиваются параллельно с существующей загрузкой.
При ошибке любого из этих двух ресурсов остаётся прежний индикатор и рабочий reply.
Это проверено с принудительной ошибкой каждого ресурса отдельно.

## Что проверить физически

1. iPhone: Safari и установленная PWA. Android: браузер и PWA, если используется.
2. Медленно потянуть влево: точка → круг/стрелка → один ripple. Продолжить держать — повторов нет.
3. Отпустить до порога, затем пересечь порог и вернуть палец назад: ответ не выбирается.
4. Отпустить после порога: выбирается ровно одно правильное сообщение.
5. Повторить на входящем/исходящем, длинном тексте, фото, видео и reply на reply, в обеих темах.
6. Вертикальная прокрутка, edge-back, контекстное меню, выбор сообщений и активная запись голосового не конфликтуют с reply.
7. Быстрые повторные свайпы, уход из комнаты во время жеста, открытая клавиатура и слабое устройство: оценить плавность и отсутствие зависшего круга.

Ограничения: программный ввод Chromium не подтверждает поведение физического Safari/WebKit,
системной клавиатуры, микрофона или вибрации. Медиа в новом тесте — тестовые карточки;
загрузка/декодирование медиа и запись реального звука этой проверкой не аттестованы.
Сравнительных замеров FPS на слабом устройстве не проводилось.
