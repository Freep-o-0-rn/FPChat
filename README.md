## 💬 О проекте

**FPChat** — экспериментальный приватный веб-мессенджер, ориентированный на быстрые личные диалоги **1-на-1**.

Основная идея проекта — получить удобство привычного мобильного мессенджера без привязки всей логики к централизованному аккаунту. Комната создаётся через приглашение или запрос по `@username`, а пользовательский интерфейс проектируется с приоритетом мобильного использования и PWA.

FPChat активно развивается. Проект уже прошёл большой путь от простого текстового MVP до клиента с медиа, голосовыми сообщениями, системным чатом, push-уведомлениями, жестами, длинной историей и отдельной архитектурой владельцев состояния.

> [!NOTE]
> **Стабильная ветка `main` сейчас соответствует Build 168.**  
> Актуальная ветка разработки — **`build/178-development`**, текущая контрольная сборка — **Build 178.28**. Серия 178 закрепляет владельцев store/history/render/read/layers/gestures/scroll/viewport без искусственной смены прежней функциональной механики. Физическая iOS/Android, push и реальный микрофон остаются отдельной ручной приёмкой.

## 🔒 Приватность и безопасность

FPChat использует **клиентское шифрование сообщений**: серверная часть работает с зашифрованным содержимым вместо открытого текста.

Упрощённо поток выглядит так:

```text
┌──────────────┐       encrypted        ┌──────────────┐
│  Browser A   │ ─────────────────────► │    Server    │
│ encryption   │                        │ SQLite / WS  │
└──────────────┘                        └──────┬───────┘
                                             │
                                      encrypted data
                                             │
                                             ▼
                                      ┌──────────────┐
                                      │  Browser B   │
                                      │ decryption   │
                                      └──────────────┘
```

### Что хранится на сервере

Серверная SQLite-база хранит технические данные, необходимые для работы мессенджера:

- комнаты и участников;
- зашифрованные сообщения (`ciphertext`, `iv`);
- служебные статусы `sent / delivered / read`;
- timestamps и технические метаданные;
- verifier для recovery-кода в виде salt + hash.

Открытый текст сообщений и открытый recovery-код серверу для хранения не требуются.

> [!IMPORTANT]
> FPChat находится в активной разработке и **не проходил независимый криптографический аудит**. Текущую реализацию нельзя считать эквивалентом проверенных production-мессенджеров только на основании наличия клиентского шифрования. Архитектура ключей, приглашений и E2EE продолжает усиливаться отдельно от пользовательской логики чата.

## 📱 UX в стиле мессенджера

При разработке FPChat новые функции должны встраиваться в существующую механику, а не заменять её параллельной реализацией.

На клиенте уже используются:

- long-press и контекстное меню сообщения;
- свайпы и мобильная навигация;
- сохранение позиции истории;
- переход к первому непрочитанному;
- reply jump;
- выделение сообщений;
- закреплённые сообщения;
- обработка экранной клавиатуры и viewport;
- очередь UI-операций и защита от поздних async-результатов;
- ограничение количества одновременно смонтированных сообщений в длинной истории.

## 🚀 Быстрый запуск

### Требования

- **Node.js 22.x**
- npm
- Windows, Linux или macOS

### Установка

```bash
git clone https://github.com/Freep-o-0-rn/FPChat.git
cd FPChat
npm install
```

### Запуск

```bash
npm start
```

После запуска приложение доступно локально:

```text
http://127.0.0.1:3010/
```

### Windows

В репозитории есть `start_chat.bat`: он проверяет зависимости и запускает актуальный сервер.

```text
start_chat.bat
```

> Скрипты развёртывания и обновления продолжают отдельно укрепляться в рамках плана Build 175. Для разработки предпочтителен обычный запуск через `npm start`.

## 🧱 Архитектура

Текущая production-ветка проекта остаётся компактным Node.js-приложением без тяжёлого клиентского фреймворка.

| Слой | Технологии / роль |
|---|---|
| **Frontend** | HTML, CSS, Vanilla JavaScript, PWA |
| **Backend** | Node.js, Express |
| **Realtime** | WebSocket (`ws`) |
| **Database** | SQLite через `better-sqlite3` |
| **Uploads** | `multer` |
| **Push** | `web-push` |
| **Client crypto** | Browser Web Crypto / клиентская криптографическая логика |
| **Diagnostics** | Runtime-метрики и регрессионные сценарии |

### Владельцы состояния

Начиная с серии Build 169–174 архитектура постепенно уходит от набора независимых обработчиков к явным владельцам ресурсов:

```text
RoomContext  ──► lifecycle / generation / cancellation
FPNetwork    ──► fetch / XHR / upload / cache
MessageStore ──► canonical message state
LayerManager ──► UI layers
Gesture      ──► pointer / touch ownership
Scroll       ──► history position / viewport
History      ──► bounded DOM / anchor loading
```

Главное правило миграции: **новый владелец не считается внедрённым, пока старый механизм продолжает независимо выполнять ту же работу.**

## 🛣️ Исходный план серии 169–175

```text
169  FPRuntime / diagnostics
 ↓
170  RoomContext / lifecycle / WebSocket ownership
 ↓
171  Network / upload / cache ownership
 ↓
172  MessageStore / reply dependencies / merge rules
 ↓
173  Layers / gestures / scroll / viewport
 ↓
174  Long history / bounded DOM / targeted rendering
 ↓
175  Server composition / media I/O / SQL / updater
```

Выше сохранён первоначальный план серии. По уточнённой области Build 175 выполняет точечные UI-исправления и регрессию; серверные изменения из первоначального плана в неё не включены. Пользовательская дорожная карта 175–180 этим изменением не редактируется.

## ⚠️ Статус проекта

FPChat — **активно разрабатываемый проект**, а не законченный коммерческий продукт.

Приоритеты разработки:

1. не ломать уже работающую пользовательскую механику;
2. не создавать параллельных владельцев одного состояния;
3. сохранять приватность пользовательских данных;
4. проверять изменения автоматической регрессией;
5. отдельно тестировать поведение на реальных мобильных устройствах.
